# cAlorie — SDGs 점심 추천

한국어 반응형 점심 추천·식사 기록 웹 앱입니다. 실제 식당 조회와 식사 기록을 서버 API·Neon 데이터베이스로 처리하며, 키 없이 식당 추천을 둘러보는 시연 모드도 제공합니다. 식사 기록은 모드에 관계없이 식약처 DB 연결이 필요합니다.

- **앱 열기:** [GitHub Pages](https://mjayj9.github.io/cAIorie/)
- **공개 앱 주소:** [cAlorie](https://caiorie.vercel.app)
- **소스 코드:** [mjayj9/cAIorie](https://github.com/mjayj9/cAIorie)

GitHub Pages는 Vercel 공개 앱으로 이동하는 진입 페이지입니다. 실제 식당·공공데이터·AI 키는 Vercel의 서버 전용 비밀 환경변수에 연결하며, 식사 기록은 Neon Free Postgres에 저장합니다. [배포 구조와 설정](docs/DEPLOYMENT.md)을 참고하세요.

## 실행

Node.js **24.x**과 npm이 필요합니다.

```powershell
npm ci
Copy-Item .env.example .env
npm run db:setup
npm run dev
```

브라우저에서 **http://localhost:5173/** 를 엽니다. 이미 `.env`가 있다면 덮어쓰지 마세요. 로컬 SQLite는 `.wrangler/state` 아래에 생성됩니다. 이 기본 개발 명령은 D1을 사용합니다. Vercel용 Next.js 실행과 DB 설정은 [배포 문서](docs/DEPLOYMENT.md)를 참고하세요.

Windows에서 PATH 또는 npm 중첩 실행 문제를 만난 경우:

```powershell
& 'C:\Program Files\nodejs\node.exe' scripts/run-framework.mjs dev
```

개발 서버를 종료했다면 위 명령으로 다시 실행하면 됩니다. 이 프로젝트는 클라이언트 저장소만 흉내 내지 않고 서버 API와 실제 로컬 D1(SQLite)를 사용합니다.

## 바로 해보기

1. **이대로 추천받기** → 원하는 보관 동의만 선택 → 연령 구간·알레르기 상태 확인.
2. **현재 위치 사용** 또는 역·건물·주소 검색 → 검색 결과를 눌러 실제 위치 선택. 어제 식사 질문은 건너뛰어도 됩니다.
3. **오늘만 조건 변경**에서 최소~최대 거리(예: 0.5km~2km), 예산과 먹고 싶은 음식을 선택합니다. 국내 조회는 20km까지 지원하며 거리는 직선거리 기준입니다.
4. 실제 식당 후보 3곳부터 비교 → **메뉴·가격 보기 / 길찾기** → **여기로 갈게요**. 나머지 식당은 더 보기로 펼칩니다.
5. 식사 후 **먹은 음식 기록** → 식약처 음식 검색 → 결과 선택 → 중량(g)과 날짜 확인 → 저장. DB에서 확인되지 않은 이름은 API로도 저장할 수 없습니다. 시연 메뉴를 먹었다고 확인할 때도 공식 음식을 선택합니다.
6. **나의 식사 기록**에서 날짜를 골라 일지를 보고 **기록 수정**으로 음식·중량·날짜·식사 시점을 수정합니다.
7. 처음 방문하면 4단계 사용 안내가 열립니다. 화면 위 **사용 방법**에서 다시 볼 수 있습니다. 전화 앱이 열리지 않으면 식당 상세의 **카카오맵에서 전화 확인**을 사용하세요.
8. **함께 먹기**에서 임시 초대 코드 또는 동의받은 동행인 간단 입력 사용.

보관 동의 없이도 추천할 수 있습니다. 기록 보관을 선택하지 않으면 식사를 확인해도 장기 식사 기록을 저장하지 않습니다. 정확한 위치나 신체 정보 없이 데모를 사용할 수 있습니다.

## 구현 범위

- 오늘 조건과 평소 기본값, 5·10점 중요도, B·C 피드백 모드.
- 독립된 알레르기·필수조건 검사, 미확인 정보 분리, 승인 후 조건 완화.
- 메뉴별 추천, 출처 상세, 데모 지도 핀과 카드 양방향 선택.
- 식약처 공식 음식만 등록·수정·섭취 확인, 중량별 추정 영양량, 날짜별 일지와 계획/실제 식사 구분.
- 동의 후 OpenRouter 무료 AI 문장 구분, 주변 식당 행정정보 확인.
- 최근 7일 기록 수·반복 관찰, 확인 뒤 기록하는 상태 전이와 중복 방지.
- 제한된 맛 선호 학습, 그룹별 메뉴·예산 검사, 비회원 초대와 동행인 입력.
- 동의 철회, 기간별 삭제, 전체 삭제, JSON 내보내기, 그룹 결과 무효화.

**Kakao·OpenRouter·식약처·행정안전부의 인증된 실제 호출을 검증했습니다.** 문장 분석 API는 성인의 별도 동의를 요구하며 음식 기록을 생성하지 않습니다. 식사 입력 화면은 식약처 DB 선택만 사용합니다. Google 해외 조회, 실제 식당 메뉴·가격, 건강 평가식, 지도 SDK·경로, 계정·보호자 확인, 앱 종료 후 알림은 별도 연결이 필요합니다. [사용법과 키 설정](API_KEY_SETUP.md)을 참고하세요.

## 데모와 실제 조회

새 설치의 `.env.example`은 `DEMO_MODE=true`이며 키는 비워져 있습니다. 실제 조회 환경은 `DEMO_MODE=false`와 OpenRouter 무료 모델을 사용할 수 있습니다. 화면도 서버 설정에 따라 실제 식당 찾기로 시작합니다. 사용자가 실제 식당 찾기를 끄면 가상 식당 6곳과 가상 메뉴·가격으로 시연합니다. 사진도 생성된 예시이며 특정 식당·메뉴의 실제 사진이 아닙니다.

실제 **장소 조회**를 시험하려면 서버 `.env`에서 `DEMO_MODE=false`와 `KAKAO_REST_API_KEY` 또는 `GOOGLE_PLACES_API_KEY`를 설정하고 재시작합니다. 서버가 실제 모드이면 화면도 실제 조회로 시작하며, 추천 전에 기기 또는 직접 선택한 위치를 요청합니다. 한국은 Kakao, 다른 국가는 Google로 연결됩니다. Google은 해당 API 활성화와 과금 설정이 필요할 수 있습니다. 이 프로젝트에서 과금 설정을 수행하지 않았습니다.

장소 API에는 검증된 메뉴별 가격이 없으므로 **실제 식당 후보**를 메뉴 추천과 구분합니다. 음식 검색어·확인된 업종·거리·선호를 비교하고, 예산·영업·포장·식사 제한 중 확인이 필요한 항목을 표시합니다. 식당 선택은 화면 안의 방문 계획이며 자동으로 식사를 저장하지 않습니다. 알 수 없는 메뉴를 생성하지 않으며, 실패 시 데모 결과로 몰래 대체하지 않습니다. 실행 환경의 demo/live 세션 키도 구분합니다. 결과가 없을 때는 후보가 실제로 늘어나는 조건 변경안만 제시하며, 모르는 가격을 이유로 예산을 올리지 않습니다.

식사 기록은 demo/live와 관계없이 실제 식약처 DB를 사용합니다. 신규 저장·수정·섭취 확인은 공통 서버 검증을 거치며, DB 장애 시 임의 입력으로 대체하지 않습니다. 이전 직접 입력 기록은 보존하고, 수정할 때 공식 항목을 선택합니다. AI 기본 OFF, 영양량은 중량 미상 시 null, 행정정보는 이름·주소가 일치한 지점만 표시합니다. 세부 설정은 [API_INTEGRATIONS.md](API_INTEGRATIONS.md)를 참고하세요.

## 검증

개발 서버를 실행한 상태에서:

```powershell
npm run typecheck
npm test
$env:RUN_API_TESTS = '1'
npm test
npm run test:e2e
npm run build
```

`npm test` 기본 실행은 순수 도메인 검사이며 HTTP 통합 검사는 건너뜁니다. `RUN_API_TESTS=1`일 때 로컬 서버와 SQLite를 함께 검사합니다. 새 실제 공공데이터·AI 통합 검사는 `RUN_CONNECTED_API_TESTS=1`, 실제 Kakao 검사는 `RUN_LIVE_KAKAO_TESTS=1`을 명시한 경우에만 실행합니다. 공개 예문과 별도 테스트 세션을 사용하고 정리합니다. 브라우저 검사는 Chromium이 필요합니다. 없으면 `npx playwright install chromium`으로 설치하세요. `TEST_BASE_URL`로 대상 로컬 서버를 바꿀 수 있습니다.

`npm run start`는 빌드한 Worker를 로컬에서 실행합니다. 공개 배포 명령이 아닙니다. 현재 실행 결과와 미검증 항목은 [TEST_REPORT.md](TEST_REPORT.md)에 있습니다.

## 구조와 문서

- `domain/`: 프레임워크 없는 타입·검증·안전·점수·식사·학습 함수
- `providers/`: 외부 I/O·응답 검증·기능 계약
- `server/`: 세션·동의·API·오케스트레이터·SQL 저장소
- `features/lunch/`: 기능별 React 화면과 상태 연결
- `db/postgres/`: Vercel용 PostgreSQL 마이그레이션
- `db/schema.ts`, `drizzle/`: 로컬 D1 스키마·마이그레이션
- `server/database/`: 공통 SQL 계약과 Neon·D1 어댑터
- `fixtures/`: 명확히 구분한 가상 데이터
- `prompts/`: 원문의 앱 내부 런타임 프롬프트, 현재 외부 모델에 전송하지 않음
- `tests/`: 도메인·HTTP 통합·실제 브라우저 검사
